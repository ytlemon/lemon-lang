# Lemon 上手教程

本教程从零开始，每一步都能直接运行。约定：所有命令都在仓库根目录执行，
`lemon` 指代构建产物（`node bin/lemon.js` 或 `dist/lemon.exe`）。

---

## 1. 第一个程序

新建 `hello.lemon1`：

```lemon
__init__ {
    main() {
        say("你好，世界")
    }
}
```

```bash
$ lemon hello.lemon1
你好，世界
```

三件事值得注意：

1. `__init__ { ... }` 是**必需的外壳**，任何 Lemon 程序都长这样。它不是函数，是程序的容器。
2. `main()` 是主程序入口声明，**不写 `def`**。程序会先执行 `__init__` 里的顶层语句，最后自动调用 `main()`。
3. `你好，世界` **没有加引号**——这就是 Lemon 的「裸文本」：不引号直接写字符串。

## 2. 变量与类型

Lemon 的变量声明必须带类型，共四种：`int`、`double`、`text`、`bool`
（`bool` 见下一节）。

```lemon
__init__ {
    int count = 3
    double price = 12.5
    text name = Lemon
    bool 有货 = true

    main() {
        say(count)
        say(price)
        say(name)
        say("有货")
    }
}
```

```
$ lemon variables.lemon1
3
12.5
Lemon
```

语句末尾**可以不写分号**，换行即断句。

类型是**静态检查**的，写错在运行之前就会被拦下：

```lemon
__init__ {
    main() {
        int a = 你好
    }
}
```

```
$ lemon bad.lemon1
错误[E0307] 类型不匹配：text（文本）的值不能赋给int（整数）变量 a
  --> bad.lemon1:3:17
   |
 3 |         int a = 你好
   |                 ^^^^
  = 提示：若想保存文字，请把类型改为：text a = ...
```

`int` 可以隐式提升为 `double`，反过来不行：

```lemon
double d = 1        // ✅ 得到 1.0
int i = 1.5         // ❌ E0307
```

## 3. 基础运算

Lemon 支持四则运算 `+ - * /` 和括号。`*` `/` 优先于 `+` `-`，同级从左往右算：

```lemon
__init__ {
    main() {
        say(1 + 2 * 3)        // 7
        say((1 + 2) * 3)      // 9
        say(10 - 2 - 3)       // 5   ← 左结合：(10 - 2) - 3
        say(8 / 4 / 2)        // 1
    }
}
```

### int 与 double

`int` 之间的除法**向零截断**，跟 C 一样：

```lemon
say(7 / 2)         // 3   ← 不是 3.5
say(0 - 7 / 2)     // -3
```

只要有一侧是 `double`，结果就是 `double`：

```lemon
double price = 12.5
say(price / 4)     // 3.125
say(7 / 2.0)       // 3.5
say(3 * 1.0)       // 3.0
```

把 `double` 结果存进 `int` 变量会被静态检查拦下：

```lemon
int total = 10 / 4.0      // ❌ E0307
double total = 10 / 4.0   // ✅ 2.5
```

### 正负号

在数值前直接加减号即可：

```lemon
int a = -5           // -5
int c = +5           // 5    ← + 是恒等，只是写出来了
double b = -2.5      // -2.5
say(-a)              // 5
say(-a * 2)          // -10   ← 等价于 (-a) * 2
say(-(1 + 2))        // -3
say(1 - -1)          // 2
say(1 + +1)          // 2
```

一元正负号的优先级**高于** `*` `/`，所以 `-2 * 3` 是 `-6` 而不是 `-(2*3)`——两者数值相同，
但换成 `-2 / 3` 时区别就出来了：它是 `(-2) / 3`。

`0 - 5` 这种写法也仍然有效（二元减法），与 `-5` 等价。

一元 `+` **不做类型转换**（不会把文本变成数字），只是数值恒等；
它和 `-` 一样只接受 `int` 与 `double`，`-你好` / `+你好` 都会报 `E0307`。

### 乘方

用 `**`，优先级**最高**且**右结合**：

```lemon
say(2 ** 10)          // 1024
say(2 ** 3 ** 2)      // 512   ← 右结合，即 2 ** (3 ** 2)
say(2 * 3 ** 2)       // 18    ← 即 2 * (3 ** 2)
say(-2 ** 2)          // -4    ← 即 -(2 ** 2)
say((0 - 2) ** 2)     // 4
```

注意 `**` 比一元负号**更紧**，所以 `-2 ** 2` 是 `-4` 而不是 `4`——想要 `4` 就加括号写 `(0 - 2) ** 2`。

`int ** int` 结果还是 `int`，但**指数不能是负数**：

```lemon
say(2 ** 10)          // ✅ 1024
say(2 ** -1)          // ❌ E0316：int 乘方不支持负指数
say(2.0 ** -1)        // ✅ 0.5   ← 把底数写成小数
say(2 ** 0.5)         // ✅ 1.4142135623730951（一侧是 double，结果就是 double）
say(2.0 ** 3)         // ✅ 8.0
```

两个边界情况也会被拦下，不会静默产生坏值：

```lemon
say(2 ** 100)             // ❌ E0406：整数结果超出安全范围
say((0.0 - 8.0) ** 0.5)   // ❌ E0408：负数开偶次方根，结果不是有限数
say(2.0 ** 10000)         // ❌ E0408：浮点溢出
```

### 用 + 拼接文本

`+` 用在两个 `text` 上是拼接，用在数字上是相加，混用则报错：

```lemon
text name = Lemon
say(你好 + ， + 世界)   // 你好，世界
say(name + 语言)        // Lemon语言
say(1 + 你好)           // ❌ E0307：数字与文本不能直接相加
```

减法、乘法、除法**只接受数字**；对文本用会报错并提示改用 `+`。

### 除以 0

除数是字面量 0 时，运行前就会拦下来：

```lemon
say(7 / 0)          // ❌ E0315 除数为 0
```

除数是算出来的则要到运行期才发现：

```lemon
int d = 1 - 1
say(7 / d)          // ❌ E0405 除数为 0，无法计算
```

### 整数溢出

`int` 运算结果超出 ±9007199254740991 会报 `E0406`，提示改用 `double`——
这样整数不会静默变成不精确的值。

```lemon
int big = 9007199254740991
say(big + 1)     // ❌ E0406
say(big / 3)     // ✅ 3002399751580330（除法截断后仍在范围内）
```

### 运算可以放在任何有表达式的位置

```lemon
__init__ {
    int a = 2 + 3 * 4       // 变量初始化

    def twice(x) {
        say(x * 2)          // 实参参与运算
    }

    main() {
        twice(a + 1)        // 运算结果作为实参
        say(a / 2)
    }
}
```

## 4. 真假值：bool、比较与逻辑

前三种类型存的是"数据"，`bool` 存的是"结论"——只有 `true` 和 `false` 两个值：

```lemon
__init__ {
    bool 已登录 = true
    bool 是会员 = false

    main() {
        say(已登录)     // true
        say(是会员)     // false
    }
}
```

`true` / `false` 是**关键字**，不会被当成裸文本。

### 比较运算：结论从哪来

`bool` 的值通常不手写，而是由比较算出来。六个比较运算符的结果**都是 `bool`**：

```lemon
int 分数 = 85

say(分数 >= 60)        // true
say(分数 == 100)       // false
say(分数 != 100)       // true
say(1 == 1.0)         // true   ← int 与 double 按数值比较
say(你好 == 你好)       // true
say(true != false)    // true
```

规则很窄，记住了就不会踩坑：

| 想比较 | 能不能用 |
| --- | --- |
| 数字与数字（`int`/`double` 随意混用） | ✅ `== != < <= > >=` 全都能用 |
| 文本与文本 | 只能用 `==` `!=`（文本没有"大小"） |
| `bool` 与 `bool` | 只能用 `==` `!=` |
| 数字与文本、`bool` 与数字 | ❌ `E0307` |

```lemon
say(1 == 你好)      // ❌ E0307
say(你好 > 世界)     // ❌ E0307：文本只支持 == 与 !=
say(true == 1)      // ❌ E0307：bool 只能与 bool 比较
```

### 逻辑运算：把结论组合起来

`&&`（并且）、`||`（或者）、`!`（取反），**两侧都必须是 `bool`**：

```lemon
bool 及格 = 分数 >= 60
bool 优秀 = 分数 >= 90

say(及格 && !优秀)      // true   ← 及格 但不是 优秀
say(优秀 || 分数 < 0)    // false
say(!(1 > 2))          // true
```

因为要求严格，`if 分数 {` 这种"数字当条件"的写法是**报错**的——必须写清楚你在判断什么：

```lemon
if 分数 { ... }        // ❌ E0318 → 判断非 0 请写 分数 != 0
if 分数 != 0 { ... }   // ✅
```

`!` 也一样：`!分数` 报 `E0307`，要写 `!(分数 > 0)` 或直接 `分数 <= 0`。

### 短路：右侧可能根本不会跑

`&&` 与 `||` 都**短路求值**——左侧已经能定下结果时，右侧整体跳过：

```lemon
int zero = 1 - 1

say(false && 1 / zero > 0)   // false  ← 右侧没执行，所以不会报除零
say(true || 1 / zero > 0)    // true   ← 同理
say(true && 1 / zero > 0)    // ❌ E0405：这次右侧真的要执行了
```

这一点在写"先检查再使用"时很有用：`if 除数 != 0 && 10 / 除数 > 1 { ... }` 不会因为除数为 0 而炸掉。

## 5. 条件分支：if / elif / else

有了 `bool`，分支就顺理成章了：

```lemon
__init__ {
    def 评级(分数) {
        if 分数 >= 90 {
            say("优秀")
        } elif 分数 >= 60 {
            say("及格")
        } else {
            say("不及格")
        }
    }

    main() {
        评级(95)      // 优秀
        评级(60)      // 及格
        评级(59)      // 不及格
    }
}
```

四个要点：

1. **条件不写括号**：`if 分数 >= 90 {`。想写 `if (分数 >= 90) {` 也可以，括号只是分组。
2. **`elif` 可以有很多个，`else` 只能有一个且在最后**。`else` 后面不能再跟条件。
3. **命中第一个为 `true` 的分支后就结束**，后面的条件连求值都不会发生。
4. 条件都不成立又没有 `else` 时，什么都不做。

### 分支是独立作用域

每个分支体都有自己的作用域：里面声明的变量出了花括号就没了，但可以遮蔽外层同名变量。

```lemon
__init__ {
    text 标签 = 内部

    def 判断(flag) {
        int 计数 = 10
        if flag {
            int 计数 = 20       // 这是分支内的新变量
            say(标签)            // 内部
            say(计数)            // 20
        } else {
            say(计数)            // 10
        }
        say(计数)               // 10 ← 上面那个 20 影响不到这里
    }

    main() {
        判断(true)
        判断(false)
    }
}
```

### 可以嵌套

```lemon
def 分类(n) {
    if n > 0 {
        if n > 100 {
            say("很大的正数")
        } else {
            say("正数")
        }
    } elif n == 0 {
        say("零")
    } else {
        say("负数")
    }
}
```

### 递归终于能收敛了

前几节里，递归只能靠 `try` 接住"调用过深"。现在可以写正常的终止条件了：

```lemon
def 倒数(n) {
    say(n)
    if n > 1 {
        倒数(n - 1)
    }
}
```

```
$ lemon countdown.lemon1   # 倒数(3)
3
2
1
```

### 常见笔误：把 == 写成 =

```lemon
if a = 1 { ... }
```

```
错误[E0202] if 的条件后应紧跟 {，这里却遇到 '='
  = 提示：判断相等要写 ==（单个 = 只用在变量声明里）
```

## 6. 循环、键盘与时间

Lemon 的循环关键字是 `cycle`，写法像一次函数调用：

```lemon
cycle(3) {          // 重复 3 次
    say("你好")
}

cycle() {           // 没有次数 = 无限循环
    say("你好")
}
```

`cycle(N)` ≈ Python 的 `for i in range(N)`，`cycle()` ≈ `while true`。

### 轮次变量 i

循环体里自动有一个 `i`，表示"现在是第几轮"，**从 0 开始**：

```lemon
cycle(3) {
    say(i)
}
```

```
0
1
2
```

因为 `i` 就是个普通的 `int`，可以直接参与运算：

```lemon
def 倒数(次数) {
    cycle(次数) {
        say(次数 - i)
    }
}
// 倒数(3) → 3 2 1
```

### 用 break 提前结束

`cycle()` 是无限的，所以必须有办法出来——`break` 跳出**最内层**的 `cycle`：

```lemon
cycle(5) {
    if i * i > 10 {
        break          // i = 4 时跳出，所以只输出 0 1 2 3
    }
    say(i)
}
```

无限循环 + `break` 能写出很多"直到满足条件为止"的逻辑：

```lemon
cycle() {
    if i >= 3 {
        break
    }
    say(i)
}
```

`break` 写在 `try` 里也**不会被 `catch` 吃掉**——它不是错误，只是一条跳出循环的捷径。

### 次数必须是 int

```lemon
cycle(3) { ... }      // ✅
cycle(0) { ... }      // ✅ 一轮都不执行
cycle(1.5) { ... }    // ❌ E0319：次数必须是 int
cycle(你好) { ... }    // ❌ E0319
cycle(-1) { ... }     // ❌ E0320：次数不能是负数（字面量，运行前拦下）
```

如果次数是算出来的负数，静态检查看不出来，运行期报 `E0409`：

```lemon
int n = 0 - 1
cycle(n) { ... }      // ❌ E0409
```

### 作用域

**每一轮都是全新的作用域**，所以体内声明的变量不会带到下一轮：

```lemon
cycle(2) {
    int 平方 = i * i     // 每轮重新声明，不会冲突
    say(平方)
}
// 0 1
```

轮次变量 `i` 会**遮蔽**外层的同名变量，循环结束后恢复：

```lemon
int i = 99
cycle(2) {
    say(i)      // 0 1  ← 这里的 i 是轮次
}
say(i)          // 99
```

反过来，在循环体里声明 `int i` 会与轮次变量冲突：

```lemon
cycle(2) {
    int i = 5   // ❌ E0306：变量 i 在该作用域内重复声明
}
```

### 嵌套

内层的 `break` 只跳出内层：

```lemon
cycle(2) {
    cycle(3) {
        if i == 2 {
            break
        }
        say(i)      // 0 1（内层每次都在 i=2 时收工）
    }
    say("下一轮")
}
// 0 1 下一轮 0 1 下一轮
```

### 三个容易踩的坑

1. **`break` 只能写在 `cycle` 体内**。写在函数体或循环之后报 `E0203`，而且要求
   **词法上**就在循环体里——被循环调用的那个函数内部写 `break` 是不行的。
2. **`i` 只能读，不能改**。Lemon 目前没有赋值语句（`=` 只出现在变量声明里），
   所以循环体里无法累积状态；真需要累加得等后续版本的赋值与函数返回值。
3. **`cycle()` 忘了 `break` 就会一直跑下去**——这正是它的语义；想停就 `break`，
   或者在终端里 Ctrl+C。

> `while` / `for` / `continue` 还没有实现，写出来会得到明确的"暂不支持"提示。

### 键盘输入：keyboard 与 waitKey

两个内置函数，配 `cycle` 就是最简的交互程序：

```lemon
cycle() {
    if keyboard(w) {          // 非阻塞：本圈有没有按 w
        say("前进")
    }
    if keyboard(q) {
        break
    }
}
```

```lemon
say("按空格继续……")
waitKey(space)                 // 阻塞：按空格之前停在这一行
say("继续了")
```

**判定语义是"按过就算"，不是"当前是否按住"。** 终端只报告"按下了什么"，
拿不到"松开了"（没有 keyup 事件），所以：

- 按一次 → `keyboard` 返回一次 `true`，读过就清零；再读是 `false`。
- 读取之前连按好几次，也只算一次（锁存，不是计数）。
- 想要"按住"的手感：在 `cycle()` 里持续轮询——键盘自动重复会不断把锁存重新置起，
  于是按住期间每圈都能读到 `true`。

**键名**：单个字符（`w`、`a`、`1`，大小写等价）或
`space` / `enter` / `esc` / `up` / `down` / `left` / `right` / `tab` / `backspace`。
中文名也认：`空格`、`回车`、`上`、`下`、`左`、`右`。

键名写成字面量时会**在运行前**校验，拼错不会被静默吞掉：

```
错误[E0321] keyboard 不认识键名「ww」
  = 提示：可用键名：单个字符（w、a、1、-）或 space / enter / esc / up / down / left / right / tab / backspace
```

**必须在真实终端里跑**。管道、重定向、REPL 里拿不到终端键盘，会明确报错：

```
错误[E0410] keyboard / waitKey 需要真实终端键盘，当前标准输入不是终端
```

这不是故意刁难——静默返回一堆 `false` 只会让人怀疑自己按键姿势不对。

**Ctrl+C 仍然好使**：读键盘时终端进入 raw 模式，Ctrl+C 不再产生中断信号，
而是被键盘层接住——程序立即停下、终端状态恢复、退出码 130。

两个注意点：

1. `cycle()` 里轮询键盘是**满速空转**，会占满一个 CPU 核心——用下一节的 `sleep` 限帧。
2. 用 `keyboard(w) == true` 是多余的（它本来就返回 `bool`），直接 `if keyboard(w) {` 即可；
   另外注意是**小写** `true`——写成 `True` 会得到专门的提示。

### 暂停与时间单位

`sleep(秒数)` 暂停一段时间——**单位是秒**：

```lemon
sleep(1)        // 1 秒
sleep(0.5)      // 半秒
sleep(0)        // 合法的空操作
```

写小数容易数不清零，所以数字后面可以直接跟时间单位：

| 写法 | 值（秒） |
| --- | --- |
| `500ms` | `0.5` |
| `2s` | `2.0` |
| `1min` | `60.0` |
| `1.5h` | `5400.0` |

```lemon
sleep(500ms)     // 和 sleep(0.5) 一样
sleep(1min)      // 一分钟
```

这类字面量**一律换算成"多少秒"的 `double`**，所以换算完就是普通数字，能直接参与运算：

```lemon
say(1min)        // 60.0
say(1min + 30)   // 90.0
say(1min / 4)    // 15.0
```

代价是它属于 `double`，所以 `int 秒 = 1min` 会报 `E0307`（提示里会告诉你换算结果是 60）。

**这里有个必须记住的坑**：既然 `sleep(1)` 是 1 秒，那 `sleep(1000)` 就是 **1000 秒（约 17 分钟）**。
从毫秒系语言过来的人极易踩。拿不准就用带单位的写法：`sleep(1000ms)`。

### 给循环限帧

把 `sleep` 放进 `cycle` 就是限帧——不然满速空转会把一个 CPU 核心跑满：

```lemon
cycle() {
    if keyboard(q) {
        break
    }
    say("帧")
    sleep(20ms)      // 约 50 帧/秒
}
```

两点补充：

- 精度受系统定时器粒度影响，偏差约 15 毫秒量级，做游戏循环够用、做精确计时不够。
- 长睡眠期间按 **Ctrl+C 也能立刻停下**，前提是程序用过 `keyboard` / `waitKey`
  （否则不会为了睡觉把终端切进 raw 模式）。
- 负数会报 `E0412`：`sleep(0 - 1)` 不是"睡一小会儿"，而是写错了。

## 7. 裸文本

裸文本是 Lemon 最"顺手"的设计：不加引号直接写文字。但它有一个**重要例外**。

### 先说例外：`say` 的文本要加引号

```lemon
say(你好)        // ❌ E0344：say 的文本要加引号
say("你好")      // ✅
text 问候 = 你好 // ✅ 别的场合可以直接写裸文本
```

`say(x)` 里的名字到底是"变量"还是"想输出的文字"最容易写混，所以规定：
**`say` 的实参写文本必须加引号**。变量 `say(count)`、数字 `say(1)` 不受影响；
其它位置（变量声明、拼接、比较等）的裸文本照旧可用。

### 裸文本的边界

```lemon
say("你好")              // ✅ 你好
say("你好，世界")         // ✅ 你好，世界（全角标点算文本的一部分）
say(Lemon v1)          // ❌ 含空格会被拆成两个词（且 say 里本来就要加引号）
say("Lemon v1")        // ✅ 需要空格时用引号
say(Hello-World)       // ❌ '-' 是保留符号，会截断裸文本
say("Hello-World")     // ✅
```

引号字符串支持转义：

```lemon
say("第一行\n第二行")
say("引号\" 反斜杠\\")
say("\u{4F60}\u{597D}")     // 你好
```

### 一个绕不开的问题：这个名字是变量还是文本？

因为变量名和裸文本长得一样，判定交给静态检查。规则很简单：

- **能查到已声明的名字** → 当成变量；
- **查不到** → 当成文本；
- **查不到，但和某个已声明的名字只差一个字符** → 报错提醒，防止打错字。

```lemon
__init__ {
    int count = 1
    main() {
        say(count)        // 1   —— 变量
        say("你好")        // 你好 —— 文本
        text 甲 = countt   // ❌ E0312：是否想使用已声明的 count？
        text 乙 = bay      // bay —— 文本（不会因为和 say 形近而误报）
    }
}
```

`say(sya(你好))` 这种把 `say` 打错的情况会得到「是否想调用 say」的提示。

## 8. 函数

用 `def` 声明函数：参数不写类型，函数没有返回值，`def` 描述的是副作用。

```lemon
__init__ {
    int version = 1

    def banner() {
        say(———Lemon———)
    }

    def greet(who) {
        say("你好")
        say(who)
    }

    main() {
        banner()
        greet(小明)
        greet(version)
    }
}
```

```
$ lemon functions.lemon1
———Lemon———
你好
小明
你好
1
```

两个要点：

- **函数提升**：`main` 里可以调用写在它后面的函数，顺序随意。
- **函数体内能看到全部顶层变量**，因为 `main()` 一定在所有顶层语句执行完之后才被调用。

参数可以遮蔽同名顶层变量，函数内的局部变量也不会泄漏出去：

```lemon
__init__ {
    text v = 顶层

    def show(v) {
        say(v)          // 参数优先 → 参数
    }

    main() {
        show(参数)
        say(v)          // 顶层
    }
}
```

### 让函数把结果带回来：return

到这一步为止，函数都只"做事"、不"给结果"。想让它算出一个值交回来，用 `return`：

```lemon
__init__ {
    def 加(a, b) {
        return a + b
    }

    main() {
        say(加(2, 3))          // 5
        say(加(1, 1) * 10)     // 20 —— 返回值就是个值，能放在任何位置
    }
}
```

`return` 一执行，函数**立刻结束**，后面的语句不再跑：

```lemon
def 绝对值(x) {
    if x < 0 {
        return 0 - x        // 提前返回
    }
    return x                // 走到这里说明 x >= 0
}
```

写成 `return` 不带值也行，含义是"到此为止"：

```lemon
def 只说话() {
    say("副作用发生了")
    return                  // 后面的都不执行
    say("这行永远不会跑")
}
```

递归也终于能把结果一层层带出来了：

```lemon
def 阶乘(n) {
    if n <= 1 {
        return 1
    }
    return n * 阶乘(n - 1)
}
```

### 返回值是什么类型？

这里有个**需要留意的取舍**。参数本来就不写类型（前面说过，参数的静态类型是"未知"），
所以返回类型也没法写死。规则只有一句：

> **函数体里有带值的 `return`，调用结果就是"未知"；没有就是 `unit`（无值）。**

```lemon
def f() { return 你好 }      // 调用结果是"未知"
def g() { say(1) }           // 调用结果是 unit

int a = f()      // ✅ 静态检查放行……但 f 实际给的是文本
int b = g()      // ❌ E0307：unit 不能赋给 int
```

第一行那种要到**运行期**才报 `E0402`。所以：想让静态检查尽量帮上忙，就让函数要么
都返回具体值、要么都别返回。另外，参数是"未知"类型时，`return a + b` 这类写法
推不出具体类型，结果必然还是"未知"——这是参数不写类型的连带代价。

### return 与 break、try 的两个区别

**一、循环里 `return` 和 `break` 不一样。** `break` 只跳出循环，`return` 直接结束**整个函数**：

```lemon
def 首个大于(数字, 阈值) {
    cycle(len(数字)) {
        if 数字[i] > 阈值 {
            return 数字[i]        // 整个函数到此结束，不是只跳出循环
        }
    }
    return 没有更大的
}
```

**二、`return` 不是错误，`try / catch` 抓不到它。** 只有真正的运行期错误才走 `catch`：

```lemon
def 安全除(a, b) {
    try {
        return a / b          // 正常时从这里返回
    } catch (错误) {
        return 错误.code      // 除零时从这里返回
    }
}
```

### 三个容易踩的坑

**一、值必须和 `return` 写在同一行。** Lemon 靠换行断句：

```lemon
def f() {
    return
    1            // ❌ 这是另一条语句，会被当成孤立的表达式（E0304）
}
```

**二、`return` 只能写在函数里。** 写在 `__init__` 顶层报 `E0204`——那里没有可返回的地方。

**三、`main()` 里不能带值返回**（`E0328`）——main 是程序入口，返回值没有人接。
不过**光秃秃的 `return` 是允许的**，含义是提前结束程序：

```lemon
main() {
    say("先说话")
    if 计数 > 10 {
        return              // 直接收工，后面的都不执行
    }
    say("继续跑")
}
```

## 9. 错误处理（try / catch）

运行期出错时程序默认会中止。想让它继续跑，就用 `try / catch` 接住：

```lemon
__init__ {
    int zero = 1 - 1

    main() {
        try {
            say("开始")
            say(7 / zero)
            say("这一行不会执行")
        } catch (错误) {
            say(错误)
        }
        say("继续")
    }
}
```

```
开始
E0405 除数为 0，无法计算
继续
```

`catch (错误)` 里的 `错误` 是一个**错误值**，可以读三个字段：

```lemon
} catch (错误) {
    say(错误)              // E0405 除数为 0，无法计算（错误码 + 说明）
    say(错误.code)         // E0405
    say(错误.line)         // 6    ← 真正出错的行号
    say(错误.message)      // 除数为 0，无法计算
}
```

### 能捕获什么

只有**运行期**错误：

| 错误码 | 场景 |
| --- | --- |
| `E0403` | 调用层数过深 |
| `E0405` | 除数为 0 |
| `E0406` | 整数运算结果溢出 |
| `E0407` | `int` 乘方的指数为负 |
| `E0408` | 乘方结果不是有限数 |

**语法错误和类型错误捕获不到**——它们在程序开始执行之前就已经中止了流程。
所以 `int a = 你好` 不会因为外面套了一层 `try` 就变成"能继续跑"。

### 兜住跑飞的递归

终止条件写错了的递归不会把解释器搞崩，而是抛出一个可以接住的 `E0403`：

```lemon
__init__ {
    def loop() {
        loop()
    }

    main() {
        try {
            loop()
        } catch (错误) {
            say(错误.code)      // E0403
        }
        say("递归被拦住了")
    }
}
```

正经的递归当然应该用 `if` 写终止条件（见第 5 节）；这里演示的是**兜底**：
调用深度上限把它变成一个事件，而不是让程序直接消失。

### 作用域与传播

- `try` 块与 `catch` 块**各自独立**：`try` 里声明的变量在 `catch` 里看不到，反过来也一样；
  外层变量两边都能用。
- `catch` 块里再抛错，错误会继续往外传播——外层还有 `try` 就能接住。
- 被接住之后调用深度会复位，可以继续正常调用函数（可以反复 `try` 同一个会失败的调用）。

### 别过度使用

`try / catch` 适合处理"意料之外的失败"。如果某个错误是可预期的，
更好的做法是**在发生前避开它**，而不是出事后兜住。

## 10. 语句分隔

默认靠换行断句。只有把多条语句写在同一行时才需要分号：

```lemon
__init__ { int a = 1; text b = 两句; main() { say(a); say(b) } }
```

忘记写分号会得到明确提示：

```
错误[E0206] 两条语句之间缺少分隔，遇到 关键字 'text'
  = 提示：Lemon 以换行断句；写在同一行时需要用 ; 分隔
```

实参也可以换行书写：

```lemon
say(
    换行实参
)
```

## 11. 引入别的文件与能力（#incloud）

程序一长就该拆开写。`#incloud` 是 Lemon 唯一的指令，它把**别的 `.lemon1` 文件**或
**内置能力模块**接进当前程序。

### 引入一个源文件

`工具.lemon1`——这是"零件"，只写 `def` 与变量，不写 `__init__`：

```lemon
def 打招呼(名字) {
    say(你好：+ 名字)
}

int 版本 = 1
```

`main.lemon1`——入口文件，把零件接进来：

```lemon
#incloud 工具

__init__ {
    main() {
        打招呼(小明)     // 你好：小明
        say(版本)        // 1
    }
}
```

几条规则：

- 写在**行首**、**独占一行**；行尾可以跟 `//` 注释。
- 路径直接写到行尾，引号可有可无：`#incloud 工具`、`#incloud 工具.lemon1`、`#incloud "工具.lemon1"` 都行；
  不带扩展名时会自动补 `.lemon1`。
- 写在 `__init__` **之前**，内容落到 `__init__ {` 之后；写在 `__init__` **里面**就地展开。
- 被引入的文件**不要写 `__init__` / `main()`**（写了报 `E0504`）。
- 同一个文件只并入一次，所以"甲引丙、乙引丙、主文件又引丙"完全没问题。

### 找不到文件时会告诉你有什么

```
错误[E0501] 找不到 工具库
  --> main.lemon1:1:10
  |
1 | #incloud 工具库
  |          ^^^
  = 提示：可用模块：web；同目录下的 .lemon1 文件：工具.lemon1、main.lemon1
```

`package.json` 这类数据文件不在支持范围内——写 `#incloud package.json` 会直接告诉你
只支持 `.lemon1` 源文件。

### 错误指向真正出错的那个文件

被引入文件里的错误，行号是**那个文件自己的**，不会算到入口文件头上：

```
错误[E0307] int（整数）与text（文本）不能用 '+' 运算
  --> lib/工具.lemon1:3:9
```

### 启用能力模块：网页

模块是一批内置函数的集合，启用后就能直接调用：

```lemon
#incloud web

__init__ {
    main() {
        text 正文 = fetchText("https://example.com")
        say(正文)
        openUrl("https://example.com")
    }
}
```

- `openUrl(网址)`——用系统默认浏览器打开
- `fetchText(网址)`——取回网页正文（`text`；超时 15 秒、正文上限 4 MB）

网址**必须加引号**：`:` 不是 Lemon 的语法符号，写 `openUrl(https://…)` 会报 `E0102`。

忘了写 `#incloud web` 就用模块函数，静态检查会告诉你补哪一行：

```
错误[E0308] 未定义的函数 fetchText
  = 提示：fetchText 来自 web 模块（网页能力：打开浏览器、抓取网页正文）；请在文件开头写 #incloud web
```

这两个函数失败时都是普通的运行期错误，可以被 `try` / `catch` 捕获。

### 用 websets() 描述一个网页

`#incloud web` 还解锁一个语言构造：`websets()`，与 `main()` 同级。

```lemon
#incloud web

__init__ {
    text 本地服务 = "localhost:9000"

    main() {
        say("逻辑照常跑在终端")
    }

    websets() {
        web.init() {
            button {
                to 本地服务                // 可以引用变量
            }
            button {
                to "https://example.com"
            }
            div (in (0,0;256,128); color=#1f6feb) {
                一块蓝色面板
                div (in (8,8;120,48); color=#ffffff) {
                    嵌在里面的白块
                }
            }
        }
    }
}
```

跑一下：

```bash
$ lemon run app.lemon1
逻辑照常跑在终端
已生成页面 app.html（2 个按钮 · 2 个 div）
```

`main()` 跑完之后，Lemon 按 `websets()` 的描述生成与入口同名的 `.html`
（`app.lemon1` → `app.html`），然后用系统默认浏览器打开。不想弹浏览器就加 `--no-open`，只落盘。

几条规则：

- `websets()` **至多一个**、不能带参数、可以完全不写（那就是纯终端程序）。
- 元素都写在 `web.init()` 里——它是页面的根容器，缺了报 `E0324`。
- 元素有三种：`button`、`div`，以及**直接写一条文本**（裸文本 / 字符串 / 变量都行）。
  名字后面直接跟 `{` 却既不是 `button` 也不是 `div`，报 `E0325`。
- `button` 需要 `to <地址>`；地址是 `text`，可以写变量。地址里的 `:` 要加引号。
- 忘了 `#incloud web` 就写 `websets()`，报 `E0323` 并提示补哪一行。

**`div` 是带位置与颜色的容器**：属性写在 `div` 后面的括号里、用 `;` 分隔，能省略不写。

- `in (x1,y1;x2,y2)`：位置盒子，两点是左上与右下，单位是像素；四个坐标都得是数字
  （可以是变量）。不写 `in` 的 div 就按普通块级元素排布。
- `color=#rrggbb`：背景色。**颜色字面量**写成 `#rrggbb`（或简写 `#rgb`），它在语言里
  就是一段文本，所以 `say(#ffffff)`、`text 主色 = #1f6feb` 也都能用。编辑器里点一下
  颜色值还能弹出取色器。
- div 里可以再放文本、嵌套 div、`button`；**嵌套 div 的坐标相对父容器**。
- 属性名只认 `in` 与 `color`，写错、重复或漏了 `;` 都报 `E0348`。

```lemon
div (in (0,0;256,256); color=#ffffff) { 内容 }
div (in (0,0;256,256)) { 只定位 }
div (color=#ffffff) { 只上色 }
div { 纯容器，按普通块排布 }
```

画布尺寸由**顶层**带盒子的 div 自动算出来（取最右、最下），所以不用手写画布大小。

**地址不带协议会自动补 `http://`**，这一步是必须的：`localhost:9000` 在 URI 语法里是
合法的（scheme 就叫 `localhost`），浏览器会把它当成协议，点了没有任何反应。

`websets` / `web.init` / `button` / `to` / `div` / `in` / `color` 都是**上下文关键字**，
只在上面这几个位置才特殊，所以这些照旧能用：

```lemon
__init__ {
    int button = 1

    main() {
        say(button)     // button —— 仍是裸文本
    }
}
```

### 只在从文件运行时有效

`#incloud` 需要文件上下文，所以 `lemon eval` 与 REPL 里用不了（报 `E0207`）——
把代码存成 `.lemon1` 再 `lemon run` 就行。

## 12. 列表

到目前为止，一个名字只能装一个值。列表让一个名字装一串值：

```lemon
__init__ {
    main() {
        list(分数) {
            90
            85
            78
        }

        say(分数)        // [90, 85, 78]
        say(分数[0])     // 90
        say(len(分数))   // 3
    }
}
```

### 声明：块式，一行一个元素

`list(名字)` 后面跟一个花括号，括号里一行写一个元素：

```lemon
list(名单) {
    小明
    小红
    小刚
}
```

元素是**任意表达式**，按书写顺序求值，所以可以引用前面声明好的东西：

```lemon
int 基准 = 60
list(成绩) {
    基准 + 30
    基准 + 25
}
say(成绩)        // [90, 85]
```

`list(name = 名字)` 也认，和 `list(名字)` 完全一样——只是把"括号里放的是列表名"写得更明白：

```lemon
list(name = 分数) {
    90
    85
}
```

### 元素类型可以不统一

`int`、`text`、`bool`、甚至另一个列表，都能混在一个列表里：

```lemon
list(杂) {
    1
    你好
    true
}
say(杂)          // [1, 你好, true]
```

代价是**取出来的元素静态类型是"未知"**：`say(分数[0] + 1)` 不会在运行前报错，
要到真跑起来才知道对不对（上例里 `杂[1] + 1` 就会在运行期炸）。
想让静态检查帮上忙，就别把类型混着放。

### 取元素：下标从 0 开始

```lemon
list(名单) {
    甲
    乙
    丙
}

say(名单[0])     // 甲
say(名单[2])     // 丙
```

下标可以是变量或表达式：

```lemon
int i = 1
say(名单[i])         // 乙
say(名单[i + 1])     // 丙
```

下标**必须是整数**（`名单[1.5]` 报 `E0307`），也**没有负数下标**——
`名单[0 - 1]` 和 `名单[99]` 一样算越界。

### 越界是运行期错误

```lemon
list(名单) {
    甲
    乙
}

say(名单[5])     // ❌ E0415 下标 5 越界：这个列表一共有 2 个元素
                 //    提示：可用的下标是 0 到 1
```

为什么不在运行前就拦下？因为**静态检查只知道类型、不知道长度**：
`名单[len(名单) - 1]` 完全合法，而长度要到运行时才算得出来。

好在它是普通的运行期错误，能被 `try` / `catch` 接住：

```lemon
try {
    say(名单[5])
} catch (错误) {
    say(错误.code)      // E0415
}
```

### len：元素个数

```lemon
say(len(名单))       // 2
```

配合 `cycle` 就能把列表从头走到尾：

```lemon
list(名单) {
    甲
    乙
    丙
}

cycle(len(名单)) {
    say(名单[i])
}
// 甲
// 乙
// 丙
```

这里 `i` 是 `cycle` 的轮次变量（第 6 节），正好拿来当下标。

### 可以嵌套

元素可以是列表，下标可以连着写：

```lemon
list(第一行) {
    1
    2
}
list(第二行) {
    3
    4
}
list(表格) {
    第一行
    第二行
}

say(表格)            // [[1, 2], [3, 4]]
say(表格[0][1])      // 2
```

### 它是声明，规则跟变量一样

`list(名字) { ... }` 不只是造一个列表，它同时**声明了一个变量**，
作用域规则和 `int a = 1` 完全相同：

- 写在 `__init__` 顶层：整个程序都能用，函数体里也看得见
- 写在块里（`if` 分支 / 函数体 / `cycle` 里）：出了块就没了

```lemon
__init__ {
    list(配置) {
        1
        2
    }

    main() {
        say(len(配置))     // 2 —— 顶层列表在函数里也能用
    }
}
```

重复声明、占用内置名，报的错和变量一模一样（`E0306`）。
元素里**引用不到自己**——绑定发生在所有元素求值完之后：

```lemon
list(a) {
    a            // ❌ E0312：此处 a 还没有声明
}
```

### 想能加能删？用编号槽与四个操作

前面那种列表是"一次写死"的。要一边跑一边往里面加、删、清空，用这四个操作：

```lemon
__init__ {
    main() {
        add list(1)              // 建一个列表，编号 1
        add[90] to list(1)       // 追加
        add[85] to list(1)

        file list(1)             // 一行一个：90 / 85
        say(list(1))             // [90, 85] —— 也能当值用

        del[90] to list(1)       // 删掉第一个 90 这个**元素**
        say(len(list(1)))        // 1

        clear list(1)            // 清空内容
        say(len(list(1)))        // 0

        del list(1)              // 删掉**整个列表**
        say(len(list(1)))        // 0 —— 再引用到的是一个新的空槽
    }
}
```

`del` 有两种形态，看关键字后面跟的是 `[` 还是 `list (`：

```lemon
del[90] to list(1)     // 删一个元素：列表还在，只是少了一项
del list(1)            // 删掉整个列表：编号 → 列表 这条绑定没了
```

`del list(X)` 只能用在**编号槽**上。命名列表是普通变量，语言里没有"取消声明"，
删了会留下"静态检查认为它还在、运行期却找不到"的裂缝，所以直接报 `E0330`——
要清空就 `clear list(名字)`，要让它彻底消失就把它声明在更小的作用域里。

还值得一提的是：`del list(1)` 删的是**绑定**，不是那个列表本身。如果别处已经拿到了
它（比如 `list(别名) { list(1) }`），那个列表照样活着：

```lemon
list(1) { 1 }
list(别名) { list(1) }
del list(1)
say(别名)            // [1] —— 值本身还在
say(len(list(1)))    // 0 —— 这里已经是另一个新空槽了
```

`list(1)` 是**编号槽**：全局容器，按编号访问，**用到就存在**，不用先声明。
`list(分数)` 则是**命名列表**——就是一个普通变量。两种列表的操作语法完全一样：

```lemon
list(名单) {
    小明
}
add[小红] to list(名单)
file list(名单)              // 小明 / 小红
del[小明] to list(名单)
say(名单)                    // [小红]
```

`list(X)` 是个普通的**表达式**，所以编号槽也能取值、参与运算：

```lemon
say(len(list(1)))
say(list(1)[0])
```

**列表是可变的**，而且指向同一个列表的名字会一起变：

```lemon
list(1) { 1 }
list(别名) { list(1) }
add[2] to list(1)
say(别名)            // [1, 2]
```

**声明就是初始化**：同一个编号或名字再声明一次，会**覆盖**原有内容，而不是追加。

`add` / `del` / `file` / `clear` 都是**上下文关键字**，只在后面紧跟 `[` 或 `list (`
时才生效——所以 `int add = 1`、`say(file)` 这些写法照常工作。

顺带一提：`file` 与 `say` 的输出刻意不同——`file` 一个元素一行，`say` 输出 `[90, 85]`。

### 三个容易踩的坑

**一、没有方括号字面量。** `[` `]` 只用来取下标，不能拿来造列表：

```lemon
say([1, 2, 3])     // ❌ E0201：Lemon 没有方括号列表字面量
```

要写列表就用块式声明。

**二、数字是编号，不是名字。** `list(1)` 说的是"1 号槽"，不是"名叫 1 的列表"：

```lemon
list(1) {          // ✅ 1 号槽（全局）
    1
}
list(分数) {        // ✅ 名字叫 分数（普通变量）
    90
}
list(true) {       // ❌ E0205：只能写整数编号或标识符
    1
}
```

选哪种看用途：要在函数之间共享、或者纯粹是"几个固定容器"，用编号槽；
要传参、要局部使用、要嵌套，用命名列表——它遵守普通变量的作用域。

**三、仍不能按下标赋值。** 能加能删了，但 `名字[0] = 60` 这种写法还不支持：

```lemon
list(分数) {
    90
}
分数[0] = 60        // ❌ E0201：Lemon 不支持给列表元素赋值
```

要改某个位置的值，可以先 `del` 掉再 `add`（会挪到末尾），或者干脆重新
`list(分数) { ... }` 写一遍。按下标赋值与元组、取余 `%` 一起留到后面的版本。

## 13. 文件读写（read / save）

程序跑完，内存里的列表、变量就消失了。要把数据留到下次——或者把结果交给别的程序——就得碰磁盘。`read { ... }` 与 `save { ... }` 就是 Lemon 干这事儿的两个**语句块**。

它们是 `read` / `save` 作**上下文关键字**：只有紧跟 `{` 才被当成文件块；所以 `text read = 1`、`text save = 1` 这类普通变量声明照样能用，不会冲突。

### 读文件：read 块

```lemon
read {
    name = "成绩.txt"        // 文件名（字符串，可用变量；不写报 E0331）
    according = "utf-8"      // 编码，可省略，默认就是 utf-8
    read in list(1)          // 把每一行作为一个文本元素，存进 list(1)
    read in say              // 同时把内容原样打印出来（可选）
}
```

`read` 块至少要有一个“落点”告诉它读到哪儿去：

- `read in list(X)`：逐行读，每行变成一个文本元素塞进列表 X。文件有 5 行，list(X) 就有 5 个元素。
- `read in say`：把内容直接打印到屏幕（不存变量，只显示）。
- `read in answer`：运行时在终端问你“要读哪一部分？”，输 `3`、`3-7`、`3,5,9` 这类行号组合即可选段（需要真实终端，管道 / 重定向下会报 `E0410`）。

可以一次读、多处落点——比如同时写 `read in list(1)` 和 `read in say`，文件只真正读一次，结果按落点分发出去。至少得有一个落点，否则报 `E0332`。

### 写文件：save 块

```lemon
save {
    name = "成绩.txt"
    according = "utf-8"
    save in list(1)          // 把 list(1) 每个元素写一行（覆盖写）
}
```

`save in list(X)` 把列表 X 的每个元素写成一行，**覆盖**原文件（不追加）。落点列表必须确实存在且是列表，否则静态检查报 `E0334`。

### 行模型与列表完全对称

这三件事是一套可逆的：

- `file list(X)`：声明列表时，把文件内容逐行读进来当元素（声明期一次性）。
- `read in list(X)`：运行时把文件逐行读进列表。
- `save in list(X)`：运行时把列表逐行写回文件。

所以“保存 → 下次再读回”能原样还原，元素顺序、个数都对得上。

### 一个完整例子：保存，再读回

```lemon
__init__ {
    main() {
        // 造点数据
        list(1) {
            小搓
            96
            "喜欢 Lemon"
        }

        // 存盘
        save {
            name = "笔记.txt"
            save in list(1)
        }

        // 下次启动再读回来
        read {
            name = "笔记.txt"
            read in list(2)
        }
        say(list(2))
    }
}
```

跑完磁盘上就有 `笔记.txt`，内容三行；再用 `read` 读进 `list(2)`，`say` 出来跟原来一模一样。

### 两个容易忽略的点

**一、路径以“运行命令的目录”为准，不是 `.lemon1` 文件所在目录。** 你在 `e:\learning python` 下执行 `lemon run 程序.lemon1`，`name = "笔记.txt"` 就会写到 `e:\learning python\笔记.txt`，而不是 `.lemon1` 文件旁边。要落到别的目录就用相对或绝对路径，例如 `name = "data/笔记.txt"`。

**二、读不到 / 写不出都会报错。** 读一个不存在的文件报 `E0902`；编码不支持报 `E0903`；写文件失败（没权限、磁盘满、路径不可写）报 `E0904`。写失败**不算运行崩溃**：`main()` 里前面的输出已经完成，退出码仍是 `0`，只是那份文件没写成。

## 14. 进目录、运行程序、删文件（fileskill）

前面 `read` / `save` 读写的是**文件内容**；这一章要动的是**文件本身**——进一个目录、
运行里面的程序、把它删掉。

> ⚠️ 这是 Lemon 最危险的能力：它会**真删文件**、**真运行程序**。只在你自己写、自己信的代码里用。

```lemon
#incloud fileskill

__init__ {
    main() {
        cd "e:/traingame" {           // 锁定到这个文件夹
            running "start.bat"       // 运行里面的 start.bat
        }
        cd "C:/Users/Administrator/Desktop" {
            delete "新建文本文档.txt"    // 删掉这个文件
        }
    }
}
```

### 三条语句

- **`cd <目录> { ... }`**：锁定一个目录。**块里面**的 `running` / `delete` 都以它为基准。
  目录不存在、或不是一个文件夹，会报 `E0417`。可以嵌套。
- **`running <文件>`**：在 `cd` 目录里运行一个文件。Windows 上 `.bat` / `.cmd` 走 `cmd /c`，
  别的类型直接执行；它的输出会原样显示出来。退出码不是 0 会报 `E0418`——可以用
  `try / catch` 兜住，让程序继续。
- **`delete <文件>`**：删掉 `cd` 目录里的一个文件。**只删文件**，不会删文件夹、不会连带
  删里面的东西（目标是文件夹会报 `E0419`）。

### 三条保护，请记住

**一、`running` / `delete` 只能写在 `cd { ... }` 里。** 写在外面会报 `E0346`。这样"在哪个
目录动手"永远是显式写出来的，不会稀里糊涂作用到当前目录。

**二、逃不出 `cd` 目录。** 想用 `..` 或绝对路径去够目录外的文件，会报 `E0420`，而且
**文件不会被碰**：

```lemon
cd "e:/data" {
    delete "../重要.txt"     // ✗ E0420：不能删 e:/data 之外的东西
}
```

**三、路径要加引号，Windows 反斜杠要写成 `/` 或 `\\`。** `delete 新建文本文档.txt` 这种裸文本
会被 `.` 拆开；而 `"e:\traingame"` 里的 `\t` 是**制表符转义**——正确写法是
`"e:/traingame"` 或 `"e:\\traingame"`。

## 15. 做一个小游戏窗口（game）

终端里玩久了，想把画面弹进一个真正的窗口？`#incloud game` 给你一个声明式的 `game()` 构造：
写清楚窗口多大、叫什么名字，Lemon 就生成一个自包含的网页窗口，双击就能看。

先看最小的一份：

```lemon
#incloud game

__init__ {
    game() {
        game.init() {
            display.win(1000, 800)     // 窗口 1000×800
            display.head("lemon")      // 窗口标题
        }
    }

    main() {
        game.running = true            // 游戏开始运行
        if game.quit == true {
            game.running = false       // 该退出了
        }
    }
}
```

保存成 `game.lemon1`，终端里 `lemon run game.lemon1`，就会在同目录生成 `game.game.html`
（1000×800、标题 lemon），并用浏览器打开。加 `--no-open` 可以只生成不打开。

### 窗口怎么描述

- `game()` 和 `main()` **同级**——写在 `__init__` 里、函数之外，不带参数，至多一个。
- `game.init()` 是窗口的“根”，两个元素写在它里面：
  - `display.win(宽, 高)`：画布尺寸，两个都必须是整数。
  - `display.head(标题)`：窗口标题，必须是文本（要加引号），也可以引用变量。
- 不写 `display.head` 就用缺省标题 `Lemon Game`；不写 `display.win` 就是 800×600。
- 整个 `game()` 由文件开头的 `#incloud game` 解锁——少了这一行会报 `E0335`，提示你补上。

### 运行状态：game.running 与 game.quit

`game` 下面挂着两个内置的真假值：

- `game.running`：游戏是否在跑。
- `game.quit`：是否要退出。

它们能读也能**赋值**：

```lemon
game.running = true        // 让它跑起来
if game.quit == true {     // 注意比较是两个等号 ==
    game.running = false   // 停下来
}
```

有一点要特别记住：**Lemon 的普通变量是不能重新赋值的**（`int a = 1` 之后再 `a = 2` 会报错）。
`game.running = ...` 是唯一的例外——语言只对 game 的运行状态开了这个口子。而且赋进去的
必须是真假值（`true` / `false`），赋个数字会报 `E0307`。

### 三个容易踩的坑

**一、`True` / `False` 要写成小写 `true` / `false`。** Lemon 只认全小写；大写会被当成
普通文本并报 `E0322`（这是特意拦的，免得跟别的语言混起来）。

**二、`==` 才是比较，`=` 是赋值。** `if game.quit = true` 是语法错误——条件里要比较，写 `==`。

**三、`game()` 不能塞进函数体。** 它和 `main()` 一样属于顶层声明，写在 `main() { ... }`
里面会报 `E0201`。

## 16. 用 class 打包字段和行为（class）

前面所有的值都是“散装”的：一个名字一个值。当“一组数据 + 一组操作”总是一起出现时，
就该把它们打包成一个**类**。`#incloud class` 给你这个能力。

```lemon
#incloud class

__init__ {
    class Student {
        text name           // 字段：类型 + 名字
        int age

        def name1(self) {   // 方法：第一个参数是接收者 self
            return self.name + "1"
        }
    }

    main() {
        Student stu = Student("小明", 18)   // 构造：按字段顺序传值
        say(stu.name)                        // 读字段
        say(stu.age)
        say(stu.name1())                     // 调方法
    }
}
```

输出：

```
小明
18
小明1
```

### 三个部分

- **字段**写在类的最前面，像变量声明但没有 `=`：`text name`、`int age`。
  **顺序就是构造时实参的顺序**。
- **方法**用 `def`，第一个参数是接收者（惯例叫 `self`），代表“当前这个对象”。
  方法体里用 `self.字段` 读自己的字段，`self.别的方法(...)` 调自己的另一个方法。
- **构造**用类名当函数：`Student("小明", 18)` 把值按字段顺序打包。声明变量时用类名当类型：
  `Student stu = ...`。

### 关于“构造函数”

Lemon **没有构造函数**（Python 里的 `__init__` 会和程序外壳 `__init__` 撞名）。
要初始化，就把值按字段顺序直接传给 `类名(...)`。

### 能做什么、不能做什么

- 能：读字段 `stu.name`、调方法 `stu.name1()`、方法里调 `self.other()`、把对象当参数传。
  `say(stu)` 会打印 `Student(小明, 18)`。
- **不能**：改字段（`stu.name = "小红"` 会报错——对象只读）、继承、`super`。
  这些和 Lemon 现有设计冲突，没有做。

### 三个容易踩的坑

**一、忘了 `#incloud class`。** 少了这行会报 `E0339`，提示你补上。

**二、方法第一个参数是 `self`。** `def greet(self) { ... }`，调用时写 `stu.greet()`，
**不用**传 `self`；写成 `stu.greet(stu)` 反而会多一个参数。

**三、字段要按顺序传全。** `Student("小明")` 只有 1 个参数、却有 2 个字段，会报“需要 2 个参数”。

## 17. 输入与分级输出（ask / output）

想让程序跟人对话，或者让日志分个轻重缓急？两个新东西：`ask(...)` 读一行输入，
`output` 按级别输出。

```lemon
__init__ {
    main() {
        text 名字 = ask(你叫什么名字？)     // 提问并读回一行
        say(名字 + "，你好！")

        output "[log]这是一条日志"
        output "[warning]这是一条警告"
        output "[error]这是一个错误"
    }
}
```

### ask：读一行输入

`ask(提示词)` 先把提示词打印出来，等你输入一行、按回车，再把这一行作为文本返回：

```lemon
text 名字 = ask(你叫什么名字？)     // 提示词可以是裸文本
text 年龄 = ask()                  // 也可以不给提示词
```

- 提示词可省略；它是文本。
- **需要真实终端**：在 REPL 里、或用管道 / 重定向喂输入时拿不到键盘，会报 `E0410`。
  想体验就写成 `.lemon1` 文件、在终端里 `lemon run`。

### output：按级别输出

`output` 后面跟一段文本，文本开头的方括号标记决定这条信息走哪：

| 你写的 | 去向 | 用途 |
| --- | --- | --- |
| `output "[error]出错了"` | **stderr** | 错误 |
| `output "[warning]注意"` | **stderr** | 警告 |
| `output "[log]完成了"` | **stdout** | 日志 |
| `output "普通信息"` | stdout | 没有标记，当普通日志 |

- 标记**不分大小写**（`[ERROR]`、`[Warning]` 都行）；只认 `error` / `warning` / `log`，
  别的 `[xxx]` 一律当普通日志。
- 标记会**原样打印**，不会被去掉。
- 文字必须是文本（要加引号）。
- 跟 `say` 的区别：`say` 永远输出到 stdout；`output` 把 error / warning 送到 stderr——
  这样 `lemon run 程序 > 结果.txt` 时，错误信息不会混进结果里。

## 18. 调试与诊断

### 只检查不运行

```bash
$ lemon check hello.lemon1
✔ hello.lemon1 检查通过
```

`--json` 输出机器可读的诊断，另有 `--warn-unused` 提示"声明后从未使用"：

```bash
$ lemon check --warn-unused variables.lemon1
```

### 看语法树与 Token 流

```bash
$ lemon ast hello.lemon1
Program
└─ __init__
   └─ FuncDecl main()
      └─ ExprStmt
         └─ Call → say
            └─ Ident 你好，世界  (裸文本)

$ lemon tokens hello.lemon1
1:1   __init__  __init__
1:10  {         {

```

静态检查后，`ast` 会把每个名字标注为 `(裸文本)` / `(变量)` / `(函数)` / `(内置函数)`，

### 一次求值

```bash
$ lemon eval 'say("你好"); say(42)'
你好
42
```

### 运行期错误的调用栈

```lemon
__init__ {
    def loop() { loop() }

    main() {
        loop()
    }
}
```

```
$ lemon recurse.lemon1
错误[E0403] 调用层数过深（超过 200 层），程序已中止
  --> recurse.lemon1:2:18
  调用栈：
    · main (第 5 行)
    · loop (第 4 行)
    · loop (第 4 行)
    ...
```

调用深度上限 200；错误**发生前**已经产生的输出会保留。
宿主（Node）堆栈不会暴露给用户。

## 21. 把 Lemon 嵌入自己的程序

除了命令行，Lemon 也可以作为库使用：

```ts
import { runSource, analyze, Evaluator, Env, renderLemonError } from 'lemon-lang';

// 最简单：直接运行
let out = '';
const result = runSource('demo.lemon1', sourceText, {
  write: (chunk) => { out += chunk; },
});
if (!result.ok) {
  console.error(renderLemonError(result.error!, result.source, 'demo.lemon1'));
}

// 只做检查
const analysis = analyze('demo.lemon1', sourceText, { warnUnused: true });
console.log(analysis.diagnostics);

// 复用环境多次运行，绑定会保留
const env = new Env();
const first = analyze('a.lemon1', 'a 的源码');
new Evaluator({ write: console.log }).runProgram(first.program!, env);
```

导出的公共 API 见 `src/index.ts`。
